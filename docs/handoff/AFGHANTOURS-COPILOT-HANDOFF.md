## 2. Stack and commands (from package.json and .github/workflows/ci.yml)
- Astro 4 (`output: 'static'`, `site: https://afghantours.com`, astro.config.mjs) + Tailwind 3 (@astrojs/tailwind). Leaflet for maps, csv-parse for data. Node 20 in CI. npm with package-lock.json.
- PHP (cPanel) for the inquiry and booking back end.
- Commands: `npm ci`; `npm run dev`; `npm run build` (= `astro build && node scripts/inject-photo-credits.mjs`, then postbuild `scripts/generate-sitemap.mjs` and `scripts/booking-copy-seed.mjs`); `npm run preview`; `npm run audit:site`; `npm run test:booking`.
- No env vars are needed for the build. Optional: `BOOKING_TODAY` (fixes "today" for booking data and tests). PHP runtime env (set on the server, never commit values): `AFGHANTOURS_PRIVATE_DIR`, `AFGHANTOURS_BOOKING_CONFIG`, `AFGHANTOURS_BOOKING_SEED_DIR`, `AFGHANTOURS_DRY_RUN_KEY` (enables inquiry dry-run), `AIM_NOW` (test clock).

## 3. CI (`.github/workflows/ci.yml`, job `qa`; runs on push to main and on every PR)
There are 18 workflow steps (GitHub adds its own setup/teardown steps, which is why the UI shows more): checkout, setup-node 20, PHP CLI, npm ci, booking data validation, booking core tests, Build, PHP lint of tour-inquiry.php, booking system tests, cancellation policy test, internal links, site integrity --strict, content slug audit, image audit (missing_count must be 0), tour sales funnel audit, inquiry entrypoint audit, tour image identity, and **dist drift check** (tracked dist/ must equal the build output).

## 4. Source vs generated
- **Source (edit these):** `src/` (pages, components, layouts, lib, content, data), `data/*.csv` (tours, attractions_master, regions, provinces, locations, hubs, activities… imported by src/lib/data.ts), `public/` (static assets, PHP: public/tour-inquiry.php, public/booking/, public/manage/, public/.htaccess), `scripts/`.
- **Generated (never hand-edit; rebuild):** `dist/` (it is **tracked in git** and is the deploy payload), dist/sitemap.xml, dist/booking/seed/, the photo-credit injections.
- Content collections: `src/content/` (attractions, hubs, provinces, regions, tours, cultural-experiences, culinary-experiences, food, restaurants, hotels, activities, pages, legal, safety, site, transport, about, homepage; schema in src/content/config.ts). Archived content: `src/content/_inactive/` (for example, the unpublished Eid experience).
- Display-name maps: src/lib/regionNames.ts, src/lib/hubNames.ts; hub catalog in src/lib/hubCatalog.ts; overrides in src/data/attractionOverrides.ts; alt text in src/data/imageAlts.ts; credits in src/data/photoCredits.ts; rejected images in src/data/rejectedImages.ts.
- Routes (src/pages): index, about, tours(/), attractions/[slug], hubs/[slug], destinations/[slug], regions/[slug], cultural-experiences/[...slug] (+ culinary/), food-culture/[...slug], restaurants, hotels, activities, transportation, specialist-services, return-journeys, custom-requests, visa-entry, cancellation-refund-rescheduling, [slug].astro (generic pages).
- Some `*.backup*` / `*.before-*` files are left in src/components; they are inert legacy copies, so leave them alone unless James asks.
